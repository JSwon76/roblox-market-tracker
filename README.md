# 로블록스 게임 수치 추적기

## 이게 왜 필요한가

제3자 트래커(RoStats, GGRecon 등)는 같은 게임 수치가 10배 넘게 어긋나기도 합니다. 원인은 단순합니다. 로블록스 공식 API는 **"지금 이 순간" 값만** 주고 과거 기록을 주지 않기 때문에, 각 트래커가 저마다 다른 간격·방식으로 찍어서 자기만의 히스토리를 만들고 있는 것입니다.

그래서 해법도 단순합니다. **우리가 직접 공식 API를 일정 간격으로 찍어서 쌓으면**, 그 기록은 출처가 확실한 우리만의 정확한 히스토리가 됩니다. 이 도구가 하는 일은 그것뿐입니다.

- 출처: `games.roblox.com` (로블록스 공식 공개 API, 로그인 불필요)
- 저장: `data\snapshots\2026-11-24.csv`처럼 날마다 한 파일 (엑셀에서 바로 열림, 2026-11-23까지는 `2026-11.csv`처럼 달마다)
- 필요한 것: 파이썬 (추가 설치 패키지 없음)

## 0. 기본은 클라우드에서 자동으로 돕니다 (PC 꺼져 있어도 됨)

이 폴더 그대로 GitHub 공개 저장소에 올려 두었고, **GitHub Actions가 10분마다** `tracker.py --once`를 실행해 결과를 저장소의 `data/snapshots/`에 커밋합니다. 설정 파일은 `.github/workflows/snapshot.yml`입니다.

- **데이터 보기:** `summary.bat`를 더블클릭하면 클라우드의 최신 데이터를 `data\cloud\`로 받아서 요약합니다. 엑셀로 보려면 `data\cloud\` 안의 CSV를 열면 됩니다. GitHub 웹에서 저장소의 `data/snapshots` 폴더를 열어 바로 내려받아도 됩니다.
- **잘 돌고 있는지:** 저장소의 **Actions** 탭. 초록 체크면 정상, 빨간 X는 그 회차 실패입니다(다음 회차에 다시 시도합니다).
- **지금 한 번 돌리기:** Actions 탭 → `snapshot` → **Run workflow**.
- **감시 게임 바꾸기:** 클라우드가 쓰는 건 저장소의 `watchlist.csv`입니다. GitHub 웹에서 그 파일을 열고 연필 아이콘으로 고친 뒤 Commit하면 다음 회차부터 반영됩니다. (`add_game.bat`는 이 PC의 목록만 바꿉니다.)
- **알아 둘 점:** GitHub 예약 실행은 붐비면 10~30분 늦거나 가끔 건너뜁니다. 그래서 간격이 고르지 않을 수 있습니다. 또 GitHub은 오래 손대지 않은 저장소의 예약 실행을 멈추기도 하는데, 그러면 메일이 오니 Actions 탭에서 다시 켜면 됩니다.
- 클라우드 저장소 주소는 `tracker.py` 맨 위 설정의 `CLOUD_REPO`에 적혀 있습니다.

아래 1~2번의 PC 실행 방법도 그대로 쓸 수 있습니다. PC에서 찍은 데이터는 `data\snapshots\`에, 클라우드에서 받은 사본은 `data\cloud\`에 따로 쌓여 섞이지 않습니다. 평소엔 클라우드만으로 충분합니다.

## 2. 실행

이 폴더(`E:\ROBLOX_PROJECT\tools\market_tracker`)에서 파일을 더블클릭하면 됩니다.

| 파일 | 하는 일 |
|---|---|
| `snapshot_once.bat` | 지금 한 번만 찍고 끝 (잘 되는지 확인용) |
| `start_tracker.bat` | **계속 추적.** 10분마다 찍음. 창을 닫으면 멈춤 |
| `summary.bat` | 최근 24시간 요약 (지금 동접, 최고, 평균, 하루 방문수, 좋아요%). 클라우드 데이터를 받아서 요약하고, 못 받으면 이 PC 데이터로 |
| `add_game.bat` | 감시할 게임 추가 (게임 주소를 붙여넣으면 됨) |

처음에는 `snapshot_once.bat`로 한 번 돌려 보고, `스냅샷 저장: 82개 게임 ...`이 나오면 `start_tracker.bat`를 켜 두세요.

명령어로 직접 쓰고 싶다면 (이 폴더에서 cmd):

```
py tracker.py                 계속 추적 (10분 간격)
py tracker.py --interval 5    5분 간격
py tracker.py --once          한 번만
py tracker.py summary         최근 24시간 요약
py tracker.py summary --hours 168    최근 7일 요약
py tracker.py summary --local        이 PC에서 찍은 데이터로 요약
py tracker.py pull                   클라우드 데이터만 내려받기 (data\cloud\)
py tracker.py add https://www.roblox.com/games/126884695634066/Grow-a-Garden
py tracker.py list            감시 목록 보기
```

## 3. 게임 추가·삭제

- **추가:** `add_game.bat` 실행 → 로블록스 웹사이트의 게임 주소(`https://www.roblox.com/games/숫자/...`)를 붙여넣기. 주소 속 숫자(플레이스 ID)를 공식 API로 유니버스 ID로 바꿔서 자동으로 넣어 줍니다.
- **삭제·이름 변경:** `watchlist.csv`를 메모장이나 엑셀로 열어 해당 줄을 지우거나 `label`을 고치면 됩니다. 다음 회차부터 반영됩니다.
- 처음 목록은 `research\roblox_hit_games_2026-11.md`에 나온 게임 21개입니다 (2026-11-22). 2026-11-23에 82개로 늘렸습니다. 각 게임은 로블록스 공식 검색·탐색 API로 찾고 `games.roblox.com` 응답으로 ID를 확인했습니다.
- **목록의 목적:** "같은 루프에서 무엇이 승자를 갈랐나" 비교. 그래서 장르마다 히트작과 같은 루프인데 못 뜬 게임을 함께 넣었습니다.
- **`memo` 형식:** `장르 / 역할 / 비고`. 역할은 `승자`(장르 대표 히트), `추격`(후발 중 성장), `부진`(같은 루프인데 못 뜸), `단독`(비교군 없음). 역할은 2026-11-23 동접 기준의 잠정 분류라 데이터가 쌓이면 바뀔 수 있습니다.

## 4. 쌓이는 데이터 (`data\snapshots\YYYY-MM-DD.csv`, 날짜는 UTC 기준)

한 회차마다 게임 하나당 한 줄씩 추가됩니다.

| 열 | 뜻 |
|---|---|
| `time_utc`, `time_local` | 찍은 시각 (UTC / 한국 시각. PC에서 찍으면 PC 시각) |
| `label` | 우리가 붙인 이름 (`watchlist.csv` 기준) |
| `playing` | **지금 동시 접속자 수(CCU)**, 모든 서버 합계 |
| `visits` | 누적 방문 수. 두 시점의 차이 = 그 사이 방문 수 |
| `favorites` | 즐겨찾기 수 |
| `up_votes`, `down_votes`, `like_pct` | 좋아요·싫어요, 좋아요 비율(%) |
| `max_players` | 서버당 최대 인원 |
| `game_updated_utc` | 그 게임이 마지막으로 업데이트된 시각. **업데이트 직후 동접이 뛰는지** 볼 때 씀 |
| `name_now` | 그 시점의 실제 게임 제목. 히트작은 제목에 `[UPD]` 같은 걸 자주 바꾸므로 기록해 둠 |

`tracker.log`에는 실행 기록과 오류가 남습니다.

### 이 데이터로 볼 수 있는 것
- **하루 방문 수 = 성장 속도.** 누적 방문은 크기, 하루 증가량은 속도입니다. 신작 판단은 속도로 합니다.
- **동접의 하루 패턴.** 언제(미국 저녁? 주말?) 사람이 몰리는지 → 우리 게임 업데이트 시각을 정하는 근거.
- **업데이트 효과.** `game_updated_utc`가 바뀐 직후 동접 변화 → 히트작이 업데이트로 얼마나 끌어올리는지.
- **트렌드 수명.** 신작의 동접이 몇 주 만에 꺾이는지.

## 4-1. 게임 프로필 (`data\profiles\`, 하루 1회, `profiler.py`)

스냅샷이 "누가 이겼나"라면, 프로필은 "왜 이겼나"의 후보를 모읍니다. 클라우드에서 매일 한국 시각 09:17쯤 자동으로 돕니다.

- `YYYY-MM-DD.csv`: 그날 게임별 한 줄
  - 진열대: `name`, `icon_id`(아이콘이 바뀌면 값이 바뀜), `thumbnail_ids`, `description`(앞 300자), `description_hash`
  - 타이밍: `created_utc`, `genre_order`(같은 장르 안에서 몇 번째로 만들어졌나), `days_after_genre_first`(장르에서 가장 먼저 만든 게임보다 며칠 늦었나)
  - 제작자: `creator_type`(User/Group), `group_members`, `creator_public_games`, `creator_other_best_name`·`creator_other_best_visits`(같은 제작자의 다른 게임 중 최고 방문)
  - 수익화: `gamepass_count`, `gamepass_min`·`median`·`max`, `gamepass_prices`
- `changes.csv`: 전날과 비교해 이름·아이콘·썸네일·설명·게임패스가 바뀐 기록. 승자가 무엇을 바꾼 뒤 떴는지 보는 용도
- 업데이트 간격은 스냅샷의 `game_updated_utc`에 10분 단위로 이미 쌓이므로 프로필에는 따로 이력을 두지 않습니다.
- 한계: "장르에서 가장 먼저"는 이 감시 목록 안에서의 순서라 진짜 원조가 아닐 수 있습니다. 클릭률·리텐션·추천 노출량은 공개 API에 없습니다.
- PC에서 직접 돌리려면: `python profiler.py`

## 5. 알아 둘 점 (한계)

- PC에서 돌릴 때는 **PC가 켜져 있고 창이 열려 있어야** 기록됩니다. 클라우드 실행은 이 제약이 없습니다.
- 과거 데이터는 만들 수 없습니다. 오늘부터 쌓입니다. **빨리 켜 둘수록 가치가 커집니다.**
- 공식 API 값도 로블록스 쪽에서 몇 분 단위로 갱신되므로, 1분보다 촘촘하게 찍는 건 의미가 없습니다. 그래서 1분 미만 간격은 막아 두었습니다.
- 레이트 리밋: 한 회차에 요청 2번(게임 50개까지 묶음)이고 요청 사이 1초를 쉽니다. 너무 많이 요청했다는 응답(429)이 오면 기다렸다가 다시 시도합니다. 10분 간격이면 한도와는 거리가 아주 멉니다.
- 용량: 82개 게임 × 10분 간격이면 하루 약 1만 2천 줄, 약 2MB. 달 파일로 두면 한 달 약 55MB가 되어 GitHub 경고선(50MB)을 넘고 커밋마다 큰 파일을 다시 쓰게 되므로, 날마다 파일을 나눕니다.

### (선택) PC 켤 때 자동 시작
`Win + R` → `shell:startup` 입력 → 열린 폴더에 `start_tracker.bat`의 **바로 가기**를 넣으면 로그인할 때마다 자동으로 켜집니다.
